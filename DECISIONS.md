# Принятые решения

- Terrain-адаптер принимает только полностью пустую зарезервированную область. Поэтому откат хранит список затронутых регионов и восстанавливает Air/0; держать исходные миллионы пустых элементов не требуется. Буферы очистки переиспользуются только внутри restore по одинаковому размеру. Проверка пустоты, резервация до yield и запрет освобождения после неудачного restore сохранены.

- Обновление13ноября: очередь осыпания ограничена исходной массой вместо4096, чтобы не терять незавершённые пустоты. Крупные очереди хранят порядок и оставшийся budget в xyzb-v1: x+74(8бит),y(7бит),z+74(8бит),budget(7бит),5символов безопасного алфавита. Конверт4 включает новый читатель и защищает от старого кода; он применяется только при >4096задач на большой форме. Общие лимиты данных: https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits . Сохранять существующие проверки массы, высотного потенциала и lease.
- Продолжение осыпания считается порциями до8задач/50ms и до2ms работы между задачами. Terrain и сетевое состояние публикуются один раз после порции, косметические переносы ограничены8; геометрия и все награды остаются серверными. Удаление устаревших задач тоже отмечает профиль изменённым.

- Расширение455→2925 растёт назад/в стороны/вверх: старые логические координаты получают z+6, origin сдвигается на−24studs. Старые пустоты и находка остаются на тех же физических местах; новые ячейки добавляются только вне старого перенесённого ядра. Все старые пустоты получают конечный бюджет осыпания, кошелёк не меняется. Layout меняет runtime-клоны, сохраняет переднюю границу и размещает музей/оборудование вне песка.
- Исходный конверт каждого размера хранится в migrationBackups до преобразования; active lease запрещает миграцию. Импорт прогресса из проверочной копии возможен только при полном совпадении исходного состояния (кроме revision) либо уже установленной той же копии с правильным резервом. Новый/изменившийся ключ не заменяется; повтор с тем же владельцем переживает потерю ответа без повторной выдачи.

- Большой сетевой Chunks может быть delta от pyramid-v1: явные атрибуты GeometryEncoding/TemplateCells включают fallback клиента. Отсутствующий изменённый чанк обязательно передаётся нулевыми битами, иначе клиент восстановил бы добытый песок. При входе выбирается меньшее из delta и sparse; режим фиксирован на эту загрузку. Для455 формат сети прежний. Изменять исходный шаблон без версионной миграции запрещено.

- World использует размер нормализованного профиля для битового поля, Terrain, проверок Remote, границ клиента и положения оборудования. Большая форма импортируется/сохраняется как чанки; старый455-профиль сохраняет совместимый формат2. Готовность мира наступает после порционной начальной публикации; во время неё сервер не принимает действия. Увеличение реального профиля остаётся отдельной миграцией.

- Перенос песка пробуждает все допустимые соседние пустоты уровнем ниже: старую пустоту нельзя окончательно забывать только потому, что сейчас над ней нет песка. Заполненная задача отменяется; координаты ограничены исходной формой, каждый перенос уменьшает высотный потенциал и не начисляет ресурсов. Для рабочей455-горы очередь вмещает каждую возможную пустоту. Лимит4096 для будущей большой горы потребует отдельной проверки переполнения до её включения.

- Управление лопатой живёт в постоянном StarterPlayerScripts.SandPrototypeShovelController: удаляемый Tool не может надёжно убрать внешние GUI/подписки из собственного Destroying. Контроллер отслеживает замену Backpack, владеет очисткой и анимирует Tool.Grip; старый Tool.SandProbeClient остаётся без обработчиков.
- У тачки одна серверная сваренная сборка и отдельное косметическое отображение рядом с камерой. Ограниченное предсказание владельца проверяет кузов/колесо на препятствия; не даёт права продажи/загрузки по клиентской позиции. Ресурс/экономика остаются в прежнем серверном контроллере. Дальние модели показываются без локального дубля.

- Основная сцена: Place 79018924370790 / Universe 10775752542. Код — `src`, сцена и модели — Studio. Перед записью Source сравнивать его с прочитанной версией; не затирать работу второго разработчика.
- Текущий рабочий прототип — 455 логических ячеек, отображаемых Roblox Terrain. Переход к большой горе — по проверяемым этапам с сохранением личного прогресса.
- Миграция 165→455 добавляет только новую массу, выполняется в UpdateAsync после проверки lease и сохраняет `legacy165Backup`. Старые добытые координаты не восстанавливаются.
- Серверная вместимость складывается из ручной переноски/рюкзака и бонуса купленной тачки. Порядок покупок не должен менять конечную вместимость.
- Клиентское наведение/подсказки учитывают фактически доступное место: ручной остаток плюс свободную близкую тачку, с учётом ожидающего подтверждения песка. Эти проверки служат обратной связи; сервер остаётся окончательным владельцем вместимости и добычи.
- Купленное оборудование выдаётся повторно после возрождения на основании серверного сохранённого флага; не требует повторной покупки и не создаёт второй Tool, если первый уже в Backpack или Character.
- Для основной игры тачка заменена наземной моделью. CartCells хранит груз как часть общего CarriedCells; цены/XP считаются по прежней общей массе. Тачка автоматически принимает добычу рядом, её груз продаётся только после доставки модели к станции. Наземная тачка остаётся после смерти; при новом входе появляется рядом с горой с сохранённым грузом.
- Начальная реализация движения тачки — серверное управление моделью с raycast/blockcast/overlap-проверками и вращением колеса. Это выбранный этап к устойчивой доставке; руки на ручках, подлинная динамика и сложные поверхности пока не объявляются готовыми.
- Осыпание: вертикальный приоритет, затем детерминированная диагональ; до 8 переносов на шаг, продолжение через очередь. Общий бюджет новой задачи — оставшаяся высота над пустотой; каждый перенос уменьшает его на1, поэтому процесс конечен. Движение не создаёт массу или награды. Рабочий профиль455 имеет высоту6 и сохраняет совместимый предел8*dugCells; большому профилю потребуется предел по его высоте.
- Осыпание, остановленное персонажем или лимитом шага, сохраняет незавершённую задачу. Старые записи budget8 читаются. Находка движется вместе с песком и сохраняется по увеличившемуся movedCells без новой добычи.
- Текущая видимая гора — Roblox Terrain. Один прежний логический элемент соответствует вокселю 4×4×4; координаты, кошелёк и число добытых элементов не пересчитываются. Сервер хранит занятость чанками по 64 бита, без proxy Parts; клиент получает те же биты и отправляет координаты намерения копать.
- Конверт сохранения 2 упаковывает геометрию в hex-чанки, сохраняя игровую схему 3 и прежние валидаторы после декодирования. Формат 1 читается; первоначальная запись профиля сохранена в локальной резервной копии. Откат к старому коду должен учитывать новый конверт. Это подготовка масштаба; ограничения 455 ячеек пока не сняты.
- Конверт3 для крупных форм хранит изменения относительно неизменного шаблона `pyramid-v1` или sparse-остаток. В памяти крупный профиль остаётся чанками; формы165/455 сохраняют совместимый список. Geometry-маски готовятся вне UpdateAsync, внутри callback валидация не yield. Общий читатель сохранений используется и для офлайн-наград.
- При проектировании записи учитывать одновременно размер ключа и throughput: [Roblox DataStore limits](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits). Шаблонные delta уменьшают регулярную запись почти целой большой горы; полностью пустая переключается на sparse, не на тысячи нулевых изменений.
- Terrain-адаптер владеет только заранее свободной областью конкретного участка, проверяет отсутствие пересечений и восстанавливает её при закрытии. Участки имеют шаг 128 studs, начало Terrain выровнено по центрам вокселей. Для копания обновляются затронутые чанки 16×16×16 studs, а не вся карта.
- Большие области Terrain создаются порциями с yield и общей резервацией. Продолжение высокого столбца проверено на стенде596×596×300; перед активацией игрового масштаба ещё требуется миграция валидаторов/шаблона. Стенд не подтверждает большой мультиплеер, мобильные устройства или экономику.
- Для сглаженной поверхности сервер подтверждает первый Terrain/Sand hit около запрашиваемой открытой ячейки (до 5 studs от её центра). Это компенсирует интерполяцию поверхности между вокселями; права, дальность, вместимость и проверка массы сохраняются.
- Удержание тачки R15 использует серверные IKControl Position для цепочек UpperArm→Hand; целевые Attachment находятся на ручках. При отпускании контролы удаляются. R6 пока получает функциональное управление тачкой без этой позы; нельзя выдавать поддержку R6-анимации за проверенную.
- Локальная история Git разрешена. Push и публикация Roblox требуют отдельного поручения. Копии пользовательских записей в `backups` не включаются в Git.
