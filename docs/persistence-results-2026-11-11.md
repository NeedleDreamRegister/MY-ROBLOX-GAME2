# Сохранение прототипа: результат проверки

## Проект и данные

- Владелец: mld8nk_kk (11883917519).
- Universe: 10775752542. Place: 79018924370790. Cloud GET подтвердил PRIVATE.
- Рабочее хранилище: DigMountainPrototype_v1, ключ shared_world_v1.
- Проверочные ключи находятся отдельно в DigMountainVerification_v1; рабочие данные не удалялись и не обнулялись.

Это одна общая маленькая гора с атомарным документом рельефа и всех счетов. Это ещё не личные участки и не масштабируемая схема большой игры. Ограничение прототипа: максимум 128 исторических профилей, исходная гора 165 ячеек, фиксированные тестовые цены.

## Серверные модули

| Explorer | Файл |
| --- | --- |
| ServerScriptService.SandPrototypeSnapshot | src/ServerScriptService/SandPrototypeSnapshot.luau |
| ServerScriptService.SandPrototypeSaveSession | src/ServerScriptService/SandPrototypeSaveSession.luau |
| ServerScriptService.SandPrototypeEconomy | src/ServerScriptService/SandPrototypeEconomy.luau |
| ServerScriptService.SandPrototype | src/ServerScriptService/SandPrototype.server.luau |

Snapshot проверяет рельеф и закон сохранения добычи/денег. SaveSession захватывает lease через UpdateAsync; чужая действующая блокировка и конфликт revision отменяют запись. Lease рассчитан на 180 секунд, обновление/автосохранение — каждые 30 секунд. При выходе и закрытии сервера выполняется финальная запись с освобождением блокировки. Исторические счета вышедших игроков удерживаются в документе.

Изменения игрового цикла выполняются без yield; сохранение получает целостную копию. Изменения, произошедшие во время сетевого запроса, остаются помечены как несохранённые. После трёх неудачных попыток записи действия останавливаются, HUD показывает ошибку; при успешном повторе работа возобновляется. При потере lease или конфликте revision сервер не перезаписывает чужой снимок. Повреждённая загрузка не заменяется начальной горой.

HUD показывает Loading, Dirty, Saving, Saved и ошибки. Автосохранение не гарантирует сохранность последних секунд при аварийном завершении: окно до 30 секунд остаётся риском прототипа. При неоднозначном сетевом исходе запись может остановиться с конфликтом и потребовать перезахода; это безопаснее повторного создания/начисления массы.

## Выполненные проверки

1. Реальный UpdateAsync/GetAsync отдельного проверочного ключа: запись и чтение успешны.
2. 17 чистых проверок Snapshot: корректные данные и отказ для повреждений/лишних монет/XP/версии/геометрии.
3. 9 проверок SaveSession на имитаторе UpdateAsync, включая повтор callback, сетевую ошибку, конфликт revision, истечение и потерю lease, release, повторную загрузку и запрет перезаписи повреждённого документа.
4. Реальный отдельный session_probe: один блок и его запас сохранены; новая сессия загрузила revision 1 и тот же счёт.
5. Реальный отдельный lease_probe: вторая сессия получила locked; первая блокировка явно освобождена. Рабочий ключ этим тестом не изменялся.
6. В настоящем игровом цикле добыто 20, продано, куплено улучшение и добыто ещё 2. Автосохранение зафиксировало 143 ячейки, DugCells=22, запас 2/40, Coins=10, XP=22, CapacityLevel=1.
7. Stop/Play: точные отсортированные имена и позиции всех 143 деталей совпали; профиль совпал целиком. В DataStore после Stop lease отсутствовал.
8. Восстановленные две ячейки проданы через E; повторная продажа не изменила деньги. После следующего Stop/Play: запас 0/40, Coins=12, XP=22, CapacityLevel=1, гора 143 ячейки, DugCells=22. HUD показал «СОХРАНЕНО».

Это проверка отдельных запусков Studio на реальном DataStore, а не проверка входа через опубликованный Roblox-клиент. Живая мобильная проверка и длительные сетевые сбои остаются открытыми.

Финальная сверка: revision 14, lease освобождён, снимок принят валидатором, все шесть исходников Studio совпали с `src`. В Edit по-прежнему 165 исходных деталей, тесты остановлены. Все девять вариантов строки статуса HUD проверены на TextFits=true. RobloxPlayerBeta.exe и обработчик roblox:// в стандартной установке не найдены; обычный клиент не запускался.

## Запуск и восстановление

У серверного Script SandPrototype атрибут PersistenceEnabled=true. Для локального многоклиентского теста с отрицательными UserId его нужно временно выключить; тестовые Player1/Player2 не записываются в настоящее сохранение. Вернуть true перед публикацией.

Источник истины кода — src. Исходная сцена в Edit содержит полные 165 ячеек; при Play рельеф восстанавливается из DataStore. Не заменять исходную сцену сохранёнными выемками вручную.

Локальный Place1.rbxl — резервная сцена первого игрового цикла, он старше нового облачного кода сохранений. Для восстановления: открыть его, опубликовать/открыть правильный тестовый проект, выполнить generated/InstallPersistence.luau в Edit и выпустить новую версию. Генератор — tools/BuildRecoveryInstaller.ps1; генерируемый файл не является отдельным источником истины.

## Публикация кода

Изменения установлены в открытой Studio. Из-за ошибок управления меню пользователь выполнил File → Publish в том же закрытом проекте и подтвердил завершение. Независимая проверка последней опубликованной версии через документированный CLI RunScript не дала выходного файла в установленной сборке Studio; доступ к истории версий через MCP токен endpoint отклонил с требованием all resources. Поэтому выпуск подтверждён пользователем, а вход через опубликованный Roblox-клиент ещё не проверен. Нельзя приравнивать успешный Stop/Play Studio к такому входу.
