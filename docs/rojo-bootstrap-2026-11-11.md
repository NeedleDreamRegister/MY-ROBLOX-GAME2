# Rojo: безопасное подключение первого скрипта

## Статус и исходный проект

Подготовлен первый этап для существующей папки `D:\Рабочий стол\роблакс ебаный`. Это не новый проект игры. Установленный CLI: `C:\tools\Rojo\rojo.exe`, версия 7.7.1; в PATH текущего терминала его нет.

Проверена открытая резервная копия `C:\Users\devv\Documents\DigTheMountain_Backup_2026-11-11.rbxl` через Studio MCP только на чтение. У неё PlaceId=0, 165 исходных ячеек, включённый SandPrototype, PersistenceEnabled=true и PersonalPlotsEnabled=true. Все 15 игровых Source совпали с локальными исходниками (сравнение без завершающих пробелов). Имя ServerScriptService.RojoManaged свободно. После подготовки хэши всех прежних 15 файлов и резервной копии остались прежними.

Существуют серверные копание/осыпание, экономика, отдельные сохранения участков, доступ и кооперация, находка/музей; клиентские управление, эффекты, HUD и посещения. Они остаются вне Rojo. Состояние другой открытой опубликованной сцены в рамках этой подготовки не сверялось и не изменялось.

Интеграция в Studio пока **не подтверждена**. Codex не запускал rojo serve, не подключал плагин, не запускал Play, не публиковал и не заменял Place.

## Конфигурация и границы

`default.project.json` читает только `src/rojo_bootstrap`. `$ignoreUnknownInstances: true` задан на DataModel, ServerScriptService и RojoManaged. В конфигурации нет Workspace/Terrain, StarterGui, ReplicatedStorage, существующих игровых скриптов или изменения свойств сервисов.

Неизвестные объекты сохраняются по правилам [формата проекта Rojo](https://rojo.space/docs/v7/project-format/). Это не защита от перезаписи объекта, имя которого уже явно описано проектом: поэтому отдельно проверено отсутствие RojoManaged. Не переносить туда игровые скрипты на этом этапе.

`servePlaceIds: [0]` разрешает подключение только к локальной копии с PlaceId=0. Поля placeId/gameId не задаются: конфигурация не привязывает копию к опубликованной игре. Если плагин отказывает по PlaceId, не снимайте ограничение: выберите именно резервную копию и сообщите результат.

Адрес — только 127.0.0.1, порт — 34873. Старый тестовый Rojo уже слушает 34872, поэтому его соединение нельзя использовать для этой проверки. Его процессы и файлы не изменялись.

## Запуск пользователем

1. Открыть PowerShell и выполнить:

   ```powershell
   Set-Location -LiteralPath 'D:\Рабочий стол\роблакс ебаный'
   & 'C:\tools\Rojo\rojo.exe' --version
   & 'C:\tools\Rojo\rojo.exe' serve .\default.project.json --address 127.0.0.1 --port 34873
   ```

2. Оставить терминал открытым. Убедиться, что сервер сообщает проект DigTheMountain-RojoBootstrap и порт 34873. Если порт занят, остановиться и сообщить ошибку; не подключаться к неизвестному серверу.
3. В Studio выбрать вкладку `DigTheMountain_Backup_2026-11-11.rbxl`, режим Edit. При необходимости открыть этот файл через File → Open from File. Не использовать вкладку опубликованного Untitled Experience.
4. В плагине Rojo отключить прежнее тестовое соединение, если оно активно. Подключиться к `127.0.0.1`, порт **34873**.
5. В предложении синхронизации проверить список изменений: ожидаются только добавление Folder RojoManaged внутри ServerScriptService и Script RojoConnectionTest внутри неё. Если предлагается удаление/перезапись игровых объектов или изменение других сервисов, отменить подключение и сообщить об этом.
6. После подключения проверить Explorer:

   ```text
   ServerScriptService
   ├── SandPrototype и прежние модули (сохранены)
   └── RojoManaged
       └── RojoConnectionTest (Script)
   ```

7. Нажать Play (F5), открыть Output. Ожидаемая строка:

   ```text
   Dig the Mountain: Rojo connected!
   ```

   В Edit строка не печатается; тестовый скрипт не создаёт объектов в Workspace.
8. Нажать Stop. Для завершения отключить плагин и нажать Ctrl+C в терминале. До проверки не перезаписывать исходный резервный rbxl. При желании сохранить проверенную сцену под новым именем `DigTheMountain_RojoBootstrap_Checked.rbxl` через Download a Copy / Save to File.
9. Сообщить результат: появились ли папка и скрипт, есть ли строка в Output, сохранились ли прежние объекты. Только после этого этап можно считать проверенным в Studio.

Локальный rbxl не содержит облачные DataStore. При PlaceId/GameId=0 прежняя система сохранений может показать предупреждение о необходимости публикации; это ожидаемое ограничение локальной копии и не результат Rojo. Не публиковать копию и не менять флаги сохранений ради этой проверки. Здесь проверяется только новый Script.

## Локальные проверки

Выполнены JSON-разбор, проверка путей и ограниченного дерева, `rojo sourcemap --include-non-scripts` и `rojo build` в отдельный проверочный XML-файл. Sourcemap содержит ровно один Script. XML содержит только ServerScriptService, Folder RojoManaged и Script с точной строкой print. Старые источники и резервный rbxl не изменены.

`generated/rojo-bootstrap-sourcemap.json` — карта соответствия. `generated/rojo-bootstrap-check.rbxlx` — только результат проверки сборки, **не полная игра**: не открывать его вместо резервной копии и не публиковать. Сборка не включает неуправляемые объекты существующей Studio-сцены.

Следующий этап — только после подтверждения пользователя: предложить последовательный перенос существующих систем со сравнением Source, зависимостей, атрибутов и ссылок, отдельной резервной копией и проверкой каждого шага. Массовая миграция в текущую задачу не входит.
