# Первый игровой цикл: интерфейс для согласования

Статус: утверждено пользователем 11 ноября 2026 года; реализуется в изолированном прототипе. Числа остаются параметрами теста.

## Проверяемый результат

Игрок копает существующую гору, заполняет переносимый запас, подходит к временной станции продажи, продаёт песок один раз и покупает одно улучшение вместимости. Два игрока имеют отдельный запас и деньги. Добытый песок не возвращается в гору после продажи.

## Разделение работы

- A: серверный учёт, ограничения копания, продажа и покупка, проверка расстояния и защиты от повторного начисления.
- B: внешний вид станции, лопаты и HUD. Для первого опыта Codex может создать временные объекты с отдельным префиксом SandPrototype; существующую сцену и будущие объекты B не заменять.
- Пользователь согласовал общий интерфейс и поручил Codex временные объекты обеих частей, A и B.

## Данные для интерфейса

Сервер создаёт Folder `Player.SandPrototypeState`. Его числовые атрибуты доступны HUD только для чтения:

| Поле | Смысл | Начальное тестовое значение |
| --- | --- | --- |
| CarriedCells | Заполненный запас в ячейках | 0 |
| CapacityCells | Вместимость | 20 |
| Coins | Монеты | 0 |
| XP | Опыт за подтверждённую добычу | 0 |
| CapacityLevel | Число купленных улучшений | 0 |

Все числа — временные параметры проверки. Ячейка пока не переводится в игровые килограммы. Эти атрибуты не являются источником истины: сервер хранит отдельное состояние и публикует снимок после операции.

## Намерения клиента и серверные операции

- `ReplicatedStorage.SandPrototypeDig(player, target)` сохраняет текущий формат: клиент отправляет только деталь. При полном запасе сервер ничего не удаляет и не начисляет.
- Продажа через `ProximityPrompt` временной станции `Workspace.SandPrototypeStation.SellPad.SellPrompt`. Сервер заново проверяет живого персонажа, расстояние и наличие песка. В одной операции обнуляет запас и начисляет цену; повторная активация пустого запаса даёт 0.
- Покупка через `Workspace.SandPrototypeStation.UpgradePad.UpgradePrompt`. Сервер проверяет цену и предел улучшения, списывает монеты, затем увеличивает вместимость. Клиент не передаёт цену или размер улучшения.
- Для первого опыта достаточно встроенных ProximityPrompt и атрибутов. Отдельные RemoteEvent продажи/покупки пока не нужны.

## Параметры опыта

Цена продажи: 1 монета за ячейку. Опыт: 1 за добытую ячейку. Одно улучшение вместимости: с 20 до 40, цена 10 монет. Все проверки и изменения одной операции выполняются без yield. Повторные активации ограничиваются на сервере.

Сохранение между сессиями относится к следующему этапу. Выход игрока в этом опыте завершает его временный запас; глобальный счётчик добытого песка горы сохраняется в текущем серверном запуске. HUD должен явно обозначать тестовый режим без сохранений.

## Проверка перед принятием

1. Заполнить 20 ячеек; 21-е копание не меняет гору и опыт.
2. Продать 20: запас 0, монеты 20; повторная продажа не начисляет ничего.
3. Купить улучшение: монеты 10, вместимость 40; повторная покупка отклоняется.
4. Два игрока копают одну цель: ячейка и награда учитываются один раз; свои монеты и запас каждый видит отдельно.
5. Отдалённая активация станции и неверная цель копания не изменяют данные.
6. Во время осыпания масса горы не меняется; `начальная масса = оставшаяся + вся добытая`, включая проданную.

## Принятое распределение

Codex реализует отдельный временный интерфейс `SandPrototypeState`, сервер A и временные станцию/HUD B. Реальные модели и оформление B смогут подключаться к тем же данным без переписывания сервера. HUD создаёт `StarterPlayer.StarterPlayerScripts.SandPrototypeHUD` в `PlayerGui.SandPrototypeHUD`.
