# Совместные раскопки: прототип

Реализованы серверные режимы Closed/Friends/Open и помощь на чужой горе. Хозяин переключает режим кнопкой «Копать у меня» в меню «Участки». Чужие станции по-прежнему недоступны; помощник продаёт добытое на своей станции. Цена и вместимость не менялись. Награду за ячейку получает тот, кто её выкопал.

## Сохранения и масса

Личные записи в DigMountainPlots_v1/player_<UserId> переходят на схему 2. Предыдущая схема 1 мигрирует автоматически с сохранением координат, денег, опыта и рюкзака. До перехода реального профиля сохранён `backups/player-11883917519-before-coop.json` — корректный JSON с массивом 139 ячеек. Прежний общий режим и общий DataStore не изменены.

Снимок 2 хранит account, outbound[helperId], imports[sourceOwnerId] и accessMode. Собственная добыча владельца = dugCells - сумма outbound. XP его кошелька = собственная добыча + сумма imports. CarriedCells + Coins + 10*CapacityLevel = XP. Геометрическая масса initialCells = RemainingCells + dugCells сохраняется отдельно. Нельзя откатить историю начислений, опыт, добычу или улучшение в последующей записи.

До первой помощи получатель сохраняет imports[source]=0. После сохранения горы её подтверждённый накопительный outbound становится основанием начисления. Получатель сохраняет кошелёк и watermark вместе; повторная доставка даёт ноль. При полном рюкзаке выдаётся только доступная часть, остаток остаётся в счётчике. После аварии получатель читает сохранённые источники снова. Подписки ограничены 128, очередь чтения последовательная с паузами и повтором. Ожидающая награда резервирует вместимость; HUD показывает её отдельно.

Пакетная запись кооперативных изменений ограничена интервалом 5 секунд на мир; финальная запись при выходе выполняется сразу, сетевые повторы — отдельно. Первое подключение помощника может потребовать подождать сохранение и повторить действие. Сбой чтения источника не считается пустым результатом: он повторяется, а HUD показывает незавершённую проверку наград.

## Проверки

- 84 проверки свежих клонов модулей: Snapshot 17, SaveSession 9, PlotData 12, PersonalSession 9, CoopData 25, CoopSession 12. Покрыты повтор callback UpdateAsync, сбой до записи, потеря ответа после записи, конфликт старой сессии, удержание lease, повторный вход после её истечения, повторная доставка, частичная выдача и запрет отката watermark.
- На настоящем DataStore в отдельном пространстве DigMountainCoopQA_v1: сохранение подписки, добычи, выдачи, повторное открытие и нулевое повторное начисление. Обе lease освобождены; рабочие профили не использовались для этого теста.
- Два локальных клиента без DataStore: Closed отвергает чужую добычу и поддельную смену режима; Open разрешает. Помощник получил 1 песок/1 XP, его гора осталась 165, чужая — 164. Хозяину чужой XP не начислялся.
- Два клиента отправили запросы к одному блоку по общему времени сервера: принят один запрос, суммарно 2 XP/2 песка после двух добытых ячеек, повторной награды нет.
- После Closed permission помощника стал false, рельеф/награды не изменились. Friends для неподтверждённого тестового ID также запрещён. Настоящий IsFriendsWithAsync вызван успешно; проверка пары реальных друзей в одном сервере пока не выполнялась. Положительный и отрицательный результат дружбы проверены в чистых тестах правил. При ошибке/неизвестном ответе доступ закрыт; результат кешируется на сессию.
- Полный рюкзак: 20 успешных дополнительных добыч, следующая отклонена. Продажа дала ровно 20 дополнительных монет; повторная продажа — ноль.
- Четыре клиента: четыре отдельных участка, три помощника добыли по ячейке на одной горе. Осталось 657 физических ячеек из 660, суммарно 3 XP/3 песка; ошибок Output нет. Это функциональная проверка, не замер FPS.
- На Galaxy A06 настоящее касание переключило Closed → Friends → Open → Closed. Все подписи/ответы помещаются. Ожидающий песок 1/20/40/165 и сообщение подключения помещаются в HUD. Для четырёх строк меню добавлена прокрутка: 148 px содержимого в окне 126 px, чтобы доступ не уходил за нижний край.
- Реальный профиль mld8nk_kk сохранил 139 блоков, 16 монет, 26 опыта и рюкзак 40. Friends пережил Stop/Play, затем режим возвращён в Closed. Ошибок Output последнего запуска не было.

## Файлы и границы

Добавлены ServerScriptService.SandPrototypeCoopData и SandPrototypeAccessRules. SandPrototypeWorld ведёт журналы наград; SandPrototypePlots управляет разрешениями и доставкой; SaveSession поддерживает валидатор и монотонность перехода. ClientContext, SandProbeClient, Feedback/HUD/Visits подключены к разрешениям и ожиданию наград. Всего 14 скриптов.

Первый тест выявил несовпадение версий: в Studio отсутствовал Economy.Credit. Метод синхронизирован точечно, добавлена проверка совместимости до загрузки мира, сценарий полностью повторён без ошибки. Пакетная замена модулей ранее была отклонена автоматической проверкой; текущее обновление применено через проверенные точечные edits, старый рабочий код сохранён.

Остаются обычный опубликованный клиент, настоящий телефон, положительная пара настоящих друзей, сетевые/FPS-замеры. Последняя публикация по-прежнему не подтверждена инструментами. Не запускать старые версии личного режима над новым форматом; они должны отказать в загрузке, а не сбросить данные. Резервные копии прежних этапов сохранены.
