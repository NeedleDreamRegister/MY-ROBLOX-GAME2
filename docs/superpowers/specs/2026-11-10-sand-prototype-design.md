# Dig the Mountain: маленький прототип песка

**Статус:** дизайн для согласования, 10 ноября 2026 года.

## Зачем

Проверить главное ощущение игры на небольшой горе: копание сверху и сбоку меняет её форму, соседний песок иногда осыпается в яму, а осыпание не создаёт массу. Это опытный образец этапа 1 из `ROADMAP.md`, а не выбор технологии для большой горы.

## Подходы

| Подход | Польза | Цена |
| --- | --- | --- |
| Сетка отдельных блоков | Понятный учёт каждой ячейки и простая проверка осыпания | Число деталей может стать проблемой; вид угловатый |
| Roblox Terrain | Более естественная форма | Сложнее доказать сохранение массы при изменении объёма |
| Сетка данных с отдельным отображением | Гибкость для будущего масштаба | Рано вводить два слоя и их синхронизацию |

**Выбрано для первого опыта:** сетка блоков. Результат теста может изменить выбор.

## Что построить

- Отдельная маленькая гора в `Workspace/SandPrototype`; размеры ячейки и горы задаются константами для теста, не балансом игры.
- Сервер хранит занятость ячеек. Один успешный клик удаляет одну доступную ячейку. Сервер проверяет, что цель принадлежит тестовой горе, ячейка ещё занята и игрок находится достаточно близко. В этом общем тесте оба игрока имеют право копать только эту гору.
- После удаления сервер делает ограниченное число локальных переносов занятых ячеек в пустые ячейки ниже. Каждый перенос очищает источник и заполняет назначение в одной операции. Счётчики `начальная масса = оставшаяся в горе + добытая масса` и `масса до осыпания = масса после осыпания` служат проверкой инварианта. Игровые килограммы пока не назначаются.
- Для ввода использовать отдельный временный инструмент `StarterPack/SandProbe`. Он передаёт серверу только целевую ячейку; количество добычи и награды клиент не задаёт. Это не лопата и не интерфейс разработчика B.
- На телефоне временный SandProbe экипируется при появлении персонажа; касание 3D-мира выбирает блок лучом из камеры. Это способ проверить песок на сенсорном экране, а не решение для будущего интерфейса оборудования.
- Код хранится в папке проекта, а копия устанавливается в Place1 по указанным путям Explorer. Пока Script Sync и Git не настроены, обновления копий выполняются явно и сверяются после установки.

## Проверка в Studio

1. Запустить Play, выкопать несколько ячеек сверху и сбоку; убедиться, что форма меняется и соседние ямы соединяются.
2. Выкопать у склона; увидеть хотя бы один перенос соседней ячейки в пустоту, затем проверить равенство счётчиков массы.
3. Повторно послать запрос по уже выкопанной ячейке и попробовать копать издалека; сервер не должен прибавить добычу.
4. Проверить двух игроков: оба видят одну форму. Записать число деталей и наблюдаемую плавность; мобильную производительность оценивать только после отдельного замера.

## Границы и открытые вопросы

В этом шаге нет монет, опыта, продажи, сохранения, личных участков и оборудования. Прототип не меняет общие данные и существующие объекты разработчика B. Порог осыпания, размер ячейки, число переносов и допустимое расстояние — параметры теста. После проверки решим, достаточно ли блочной модели или нужен Terrain либо гибрид.
