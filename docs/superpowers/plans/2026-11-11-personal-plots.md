# Личные участки прототипа

**Цель:** отдельные гора/экономика/сохранение/появление для каждого игрока. Исполнение самостоятельное по поручению пользователя.

**Архитектура:** извлечь существующий цикл горы в фабрику SandPrototypeWorld.Start(config); Economy.Create(owner) создаёт независимый счёт. SandPrototypePlots назначает четыре тестовых слота и клонирует текущую сцену только в Play. Предыдущий общий режим остаётся в серверном скрипте за флагом PersonalPlotsEnabled=false. Все цены, масса и осыпание сохраняются. ObjectValue Player.SandPrototypeMountain указывает клиенту его гору; имена SandPrototypeState и SandPrototypeDig сохраняются. Чужую гору/станцию меняет только владелец (кооперация — следующий этап).

**Хранение:** DigMountainPlots_v1 / player_<UserId>. Первичная копия legacy допустима только при единственном профиле владельца и отсутствии действующей lease; старый ключ не удаляется и не переписывается. Существующее личное сохранение имеет приоритет. При неоднозначности или ошибке чтения никакого пустого прогресса вместо старого. Старые опубликованные общие версии нельзя использовать параллельно с переносом: последующие изменения legacy не объединяются с личным миром.

**Проверки и риски:** четыре слота — параметр маленького теста, не готовый размер сервера. Исчезновение игрока во время загрузки/сохранения, повторный вход, занятая lease, чужие запросы, слоты и восстановление рельефа должны быть проверены. Слот освобождается после завершения/неудачи финального сохранения; при сетевом сбое оставшаяся lease защищает запись до истечения. Один общий исходный шаблон, изменения только runtime.
